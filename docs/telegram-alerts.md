# Уведомления сотрудникам в Telegram

Сайт отправляет в один Telegram-чат сотрудников короткие сообщения:

- **оплачен заказ с сайта** (anvi.md) — номер, сумма, доставка, товары, ссылка в админку;
- **новая заявка компании** («Pentru companii» на anvi.md/companii) — компания, контакт, товары, тираж, срок, ссылка на заявку;
- **новый неоплаченный заказ с сайта** — по желанию, по умолчанию выключено (см. шаг 4).

Пока переменные окружения не заданы, сообщения только пишутся в лог сервера (Vercel → Logs, строки `[telegram] (not configured) …`) и ничего не ломают.

## 1. Создать бота через @BotFather

1. В Telegram откройте [@BotFather](https://t.me/BotFather) (с синей галочкой).
2. Отправьте `/newbot`.
3. Введите имя бота, например `ANVI уведомления`.
4. Введите username — должен заканчиваться на `bot`, например `anvi_studio_alerts_bot`.
5. BotFather пришлёт **токен** вида `1234567890:AAH…`. Это пароль бота: никому не пересылайте и не публикуйте его. Если токен утёк — в @BotFather `/revoke`.

## 2. Добавить бота в группу сотрудников

1. Создайте группу (например «ANVI — заказы») или используйте существующую.
2. Добавьте в неё бота: «Добавить участников» → поиск по username бота.
3. Напишите в группе любое сообщение, например `привет`.
   (Если бот не видит сообщений: в @BotFather → `/mybots` → бот → Bot Settings → Group Privacy → **Turn off**, затем напишите в группу ещё раз. Для отправки уведомлений это не обязательно — нужно только чтобы узнать chat id.)

## 3. Узнать chat id группы

1. Откройте в браузере (подставьте свой токен):

   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`

2. В ответе найдите блок `"chat": { "id": -100…, "title": "ANVI — заказы", "type": "supergroup" }`.
3. Число `id` (для групп оно **отрицательное**, часто начинается с `-100`) — это `TELEGRAM_STAFF_CHAT_ID`.
4. Если `result` пустой (`"result": []`) — напишите в группу ещё одно сообщение и обновите страницу.

Можно и в личный чат: напишите боту `/start` в личке, тогда в `getUpdates` будет ваш личный id (положительное число).

## 4. Задать переменные в Vercel

Vercel → проект → **Settings → Environment Variables** → добавить для окружения **Production** (и при желании Preview):

| Переменная | Значение | Обязательно |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | токен от @BotFather | да |
| `TELEGRAM_STAFF_CHAT_ID` | chat id группы, например `-1001234567890` | да |
| `TELEGRAM_ALERT_UNPAID_ORDERS` | `1` — присылать и неоплаченные заказы с сайта | нет (по умолчанию выключено) |
| `ADMIN_PUBLIC_BASE_URL` | адрес админки для ссылок в сообщениях | нет (по умолчанию `https://print.anvi.md`) |

После сохранения сделайте **Redeploy** последнего деплоя — переменные подхватываются только новым деплоем.

## 5. Проверить

1. Зайдите на print.anvi.md → **Настройки** → раздел **«Уведомления»**.
2. Там видно, подключён ли Telegram и какой chat id задан (токен не показывается).
3. Нажмите **«Отправить тест»** — в группу придёт сообщение «✅ Тест уведомлений ANVI».

Если тест не пришёл:

- «Telegram не принял сообщение» — неверный токен или chat id, либо бота удалили из группы. Проверьте `getUpdates` ещё раз.
- «Telegram не настроен» — переменные не заданы или не было Redeploy.

## Как это устроено (для разработчиков)

- Модуль: `src/lib/notify/telegram.ts` (отправка + форматирование), `src/lib/notify/staffAlerts.ts` (события).
- Отправка всегда после ответа (`runAfter`), ошибки только логируются — оплата, checkout и форма заявки от Telegram не зависят.
- «Оплачен» отправляется один раз: только на вызов, который действительно перевёл заказ в оплаченные (`markShopOrderPaid` → `"paid"`). Повторные вызовы оплаты сообщений не дублируют. Будущий callback Paynet должен делать так же (см. `src/lib/shop/payment.ts`).
